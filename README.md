# ComfyUI_ZXin — 图像批处理与分发节点集

面向 ComfyUI 的批量图像处理节点包：把「加载图像」从单张手工拖拽升级为**目录级批量扫描 → 文件夹预览 → 自动逐批执行 → 批量落盘**的完整链路。

- 目标版本：ComfyUI ≥ 0.3.0（已在 **0.42.0 / Windows 便携版 G313** 实测通过）
- 当前版本：**v1.1.0**（更新记录见 [CHANGELOG.md](CHANGELOG.md)）
- 节点契约：V1 Schema（`NODE_CLASS_MAPPINGS`）
- 界面语言：**全部参数名、输出名、说明均为中文**
- 额外依赖：**无**，只使用 ComfyUI 自带的 torch / numpy / Pillow

---

## 先看这里：3 分钟上手

### 方式一：导入现成工作流（推荐）

1. 重启 ComfyUI
2. 菜单栏点 **工作流 → 浏览模板**
3. 找到分类 **ComfyUI_ZXin**，选：
   - `ZXin_01_批量加载与预览` —— 最小链路，先看看文件夹里有什么
   - `ZXin_02_多轮自动执行` —— 完整链路，演示「只按一次运行跑完所有批次」
   - `ZXin_03_四路并行分发` —— 一批图分给 4 个不同节点并行处理
4. 导入后只需改**加载器**的「加载来源」，选你的文件夹（如 `input/Pose图`），然后点运行

### 方式二：手动连（3 个节点）

```
① 批量图像加载器  ──图片列表──→  ② 批次分发器  ──批次列表──→  ④ 批量保存器
        │                            每批输出张数 = 4
        └──文件夹预览图──→ [内置 PreviewImage 节点]（可选，先看看文件夹内容）
```

三步：
1. 加 **①批量图像加载器**，「加载来源」选 `input/你的子文件夹`，**看输出端口旁边的预览图**确认内容
2. 加 **②批次分发器**，「每批输出张数」填 4，把①的「图片列表」连到②的输入
3. 把②的「批次列表」连到你想要的处理节点（采样/放大等），最后连到 **④批量保存器**

> **就这样。** 点一次运行，下游会自动按批次数逐轮执行，跑完所有批次。

## 核心能力：按一次运行，自动跑完全部批次

这是本节点包最关键的设计。

**批次分发器** 的「批次列表」输出是一个**列表**，里面装着若干批图片。ComfyUI 的执行引擎检测到列表输出后，会把下游节点**按批次数自动执行多次**——每轮收到一批图片，跑完这一轮自动接下一轮，直到全部批次处理完毕。

例：input 子文件夹里有 20 张图，「每批输出张数」设为 **4**：

| 轮次 | 收到图片 | 说明 |
| --- | --- | --- |
| 第 1 轮 | 第 1–4 张 | |
| 第 2 轮 | 第 5–8 张 | |
| 第 3 轮 | 第 9–12 张 | |
| 第 4 轮 | 第 13–16 张 | |
| 第 5 轮 | 第 17–20 张 | |

**全程只需点击一次运行按钮。** 下游的采样、放大、保存等节点会依次跑完 5 轮。

## 节点清单（5 个）

节点显示名带 ①②③④ 序号，就是推荐使用顺序。

### ① 批量图像加载器

扫描目录并把多张图片加载成一个 `IMAGE` 批次，**同时输出文件夹缩略图拼贴**。

| 参数 | 说明 |
| --- | --- |
| `加载来源` | 目录下拉，含 `input`、`output` 及其**子目录**（如 `input/Pose图`），可直接选 input 子文件夹 |
| `文件名匹配` | 通配符，如 `*.png`、`Pose_*` |
| `排序方式` | 按名称升序 / 降序、按修改时间新到旧 / 旧到新、随机 |
| `随机种子` | 随机排序的种子。控件上可设「生成后=随机」，每次排队自动换一批 |
| `最多加载张数` | 最多取几张，`0` = 全部 |
| `载入设备` | 跟随系统 / 仅CPU（批量大图建议仅CPU） |
| **`生成预览拼贴`** | 是否生成文件夹预览图（默认开） |
| **`预览列数`** | 拼贴几列排列 |
| **`预览单格大小`** | 每格缩略图边长（像素） |
| `自定义路径` | 任意绝对路径，填写后优先生效 |
| `含子文件夹` | 是否递归扫描子目录里的图片（默认关 = 只扫一层） |
| `限制最大边长` | `0` = 完全保留原始尺寸；`>0` 时把长边等比缩放到不超过该值，**防大目录爆内存** |
| **`加载模式`** | `自动（超内存阈值才惰性）`（默认）/ `全部载入（不惰性）` / `惰性分批`，见下方「惰性分批加载」 |
| `单批内存上限` | 单位 MB。`0` = 自动取可用资源的 25%；`>0` 时按该值切分每批张数。仅分批时生效 |

输出：
- **`图片列表`** —— 图片列表，每张独立成张并**保留原始尺寸**（尺寸不同也没关系）
- **`文件夹预览图`** —— 一张网格拼贴图，每格带文件名角标，**一眼看清文件夹里有什么**
- `文件名列表` —— JSON 数组，可连给保存器/标注器保持源文件对应关系
- `加载数量` —— **本批**实际加载张数（惰性模式下不等于目录总数）
- `加载进度` —— 如「惰性分批：已加载 117/565 张（第 2/5 批）」

> **预览图怎么用**：把「文件夹预览图」连到内置的 **PreviewImage（预览图像）** 节点，运行后就能在画布上看到整份拼贴。调「预览列数」和「预览单格大小」让缩略图更清晰。
>
> **尺寸不再受限**：加载器**保留每张图的原始尺寸**，不再强制统一。不同分辨率的图混在同一个文件夹里也能正常加载和分发——因为下游是**逐张**接收的，同一节点的多个 image 输入口也可以各自接不同尺寸的图。
>
> **内存提示**：目录较大时会自动启用**惰性分批**（见下），不必再手动调
> 「最多加载张数」。若不想分批，把「加载模式」设为 `全部载入（不惰性）` 即可回到一次性载入。

## 惰性分批加载

几百上千张高分辨率原图一次性载入会撑爆内存。本包实测 `input/角色卡`
565 张（均 8.7 MP）需要约 **55 GB**，普通机器必然 OOM。

加载器现在会按内存预算**一次只解码一小批**，跑完自动续排下一批，
直到全部处理完 —— **你只需要点一次运行**。

### 为什么是「分批」而不是「延迟解码」

ComfyUI 的 IMAGE 端口只收 float32 张量，加载器返回 N 张就必然同时驻留
N 张，架构上不存在「用到时再解码」的空间。所以唯一有效的省内存手段就是
控制**一次解码多少张**。

已确认 ComfyUI 的缓存在新 prompt 时会清掉上一批的输出（`_clean_cache`
删除非当前使用项），所以多批跑下来**不会累积**，峰值始终等于单批大小。

### 判定规则

| 项 | 取值 |
| --- | --- |
| 触发阈值 | 预估总量 > 可用资源的 **50%** 才启用惰性 |
| 单批预算 | 默认可用资源的 **25%**（比阈值保守，给模型权重留余量） |
| 设备感知 | 张量在 CUDA 上时按**显存**算预算，不再误用系统内存 |

「加载模式」可强制切换：
- `自动（超内存阈值才惰性）` —— 默认，小目录零额外开销
- `全部载入（不惰性）` —— 强制一次性载入（v1.1 及以前的行为）
- `惰性分批` —— 无论大小都分批

### 实测效果

| 场景 | 方式 | 峰值内存 |
| --- | --- | --- |
| 60 张 1600×1200 | 一次性载入 | +1575 MB |
| 60 张 1600×1200 | 惰性分批（预算 300 MB） | **+423 MB（-73%）** |
| `角色卡` 565 张 | 一次性载入 | ~55.1 GB |
| `角色卡` 565 张 | 惰性分批（自动） | **~11.4 GB（-79%）** |

### 自动续跑是怎么做的

跑完一批若还有剩余，后端通过 WebSocket 发 `zxin.lazy_continue` 事件，
前端 `js/lazy_auto_queue.js` 收到后自动再排一次队，直到全部跑完。
后端游标以节点 ID 为键，多个加载器节点互不干扰。

前端扩展不可用时（老版本 ComfyUI、扩展被禁用）会**降级为手动重复运行**，
不影响正确性 —— 每点一次运行处理一批，看「加载进度」输出即可知道还剩多少。

全程跑完后再点运行，会**从第 1 张重新开始**。

### ② 批次分发器（自动逐批执行）

**本包核心节点**。把图片每「每批输出张数」张分成一批，输出**批次列表**，驱动下游自动多轮执行。

| 参数 | 说明 |
| --- | --- |
| `每批输出张数` | 一批输出几张。20 张图 + 每批 4 张 = 5 轮 |
| `丢弃不足一批的余数` | 最后不足一批时是否丢弃（否则最后一批会短一些） |
| `变尺寸处理方式` | 批内图片**尺寸不一致**时怎么办（见下表） |

输出只有 3 个：

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| `批次列表` | IMAGE | **要接到下游的那个口**。里面装着若干批，按顺序排好 |
| `分批清单` | STRING | JSON，记录分组数、执行轮数、每批张数与各批尺寸 |
| `执行轮数` | INT | 下游实际会被调度几次 |

> **`批次列表` 里究竟是什么？**
> 例：20 张图、每批 4 张（尺寸一致）→
> `批次列表` = [ [图1~图4], [图5~图8], [图9~图12], [图13~图16], [图17~图20] ]
> 下游节点接到这个口，会被自动调用 **5 次**：第 1 次收到图1~图4，第 2 次收到图5~图8……

#### 批内尺寸不一致时怎么办

一个 IMAGE 端口一次只能接收**一个张量**，而张量要求批内 H/W 相同，
所以「一批里装着不同尺寸的图」在 ComfyUI 里物理上无法直接成立。
用 `变尺寸处理方式` 选择取舍：

| 选项 | 一批 N 张会跑几轮 | 尺寸 | 适用 |
| --- | --- | --- | --- |
| **逐张单独执行（保留原始尺寸）**（默认） | N 轮，每轮 1 张 | **完全不动，原样保留** | 要保持原分辨率的场景 |
| 留白统一到批内最大尺寸 | 1 轮 N 张 | 等比缩放后补黑边，统一成批内最大尺寸 | 能接受黑边、想少跑几轮 |
| 等比裁切到批内最小尺寸 | 1 轮 N 张 | 等比缩放后居中裁切，统一成批内最小尺寸 | 能接受裁掉边缘 |

批内尺寸**恰好一致**时不受影响：自动拼成一个 `[N,H,W,3]` 张量，仍是 1 轮 N 张。

### ③ 并行分发器（可调分支数）

把图片**轮流**分到多个分支输出，每个分支接一个不同的节点。

| 参数 | 说明 |
| --- | --- |
| `分支数` | 用几个分支（**1–12**） |

**输出端口会随「分支数」自动增减** —— 改这个数值，节点右侧的分支端口立刻变多/变少，
不用手动增删。最多 12 路。

分配规则（20 张图、4 分支为例）：

| 分支 | 拿到哪些图 |
| --- | --- |
| 分支1 | 第 1、5、9、13、17 张 |
| 分支2 | 第 2、6、10、14、18 张 |
| 分支3 | 第 3、7、11、15、19 张 |
| 分支4 | 第 4、8、12、16、20 张 |

分支数改成 6 时，分支1 拿第 1、7、13、19 张，分支2 拿第 2、8、14、20 张，以此类推。

每张图**保持原始尺寸**。各分支可以接不同节点，
也可以接同一个节点的多个 image 输入口。

> **端口为什么能增减？** 后端固定注册 12 路输出以保证执行契约稳定，
> 前端扩展（`js/dynamic_branch_outputs.js`）根据「分支数」实时裁剪可见端口。
> 调小分支数再调回来，已连的线还在。

### ④ 批量保存器

批次逐张落盘，并写入 PNG 元数据。

| 参数 | 说明 |
| --- | --- |
| `文件名前缀` | 支持 ComfyUI 的 `%date%` 等变量 |
| `命名方式` | 按序号 / 沿用源文件名 / 前缀加源文件名 |
| `文件名列表` | 接加载器的 `文件名列表` 即可保持源文件对应关系 |
| `写入元数据` | 写入 prompt / workflow 元数据 |

> 同名文件**不会覆盖**，自动追加 `_001` 后缀。

### ⑤ 批量角标标注器

给每张图叠加编号 / 文件名角标，用于核对批量处理与分发的对应关系。

| 参数 | 说明 |
| --- | --- |
| `标签内容` | 序号和文件名 / 仅序号 / 仅文件名 / 不添加 |
| `标签位置` | 四角定位 |
| `字号` `文字颜色` `背景颜色` | 外观 |
| `文件名列表` | 接加载器输出即可显示源文件名 |

角标用 PIL 绘制，**支持中文文件名**（自动使用 msyh.ttc 等中文字体）。

## 常见接法

### 全自动多轮出图

```
①加载器 ──图片列表──→ ②分发器 ──批次列表──→ KSampler ──→ VAE解码 ──→ ④保存器
                        (每批4张)            ↓                      ↑
                     分批清单 ─────────→ 文件名列表 ─────────────────┘
```

要点：
1. 加载器 `加载来源` 选 `input/Pose图`（或任意子目录）。
2. 分发器 `每批输出张数` 填 4 → 20 张图自动跑 5 轮。
3. 保存器接加载器的 `文件名列表` → 落盘文件名与源文件一一对应。
4. **图尺寸不一致时**：分发器默认「逐张单独执行」，一批 4 张会跑 4 轮、
   每轮 1 张，尺寸原样保留。想保持「一轮 4 张」就把 `变尺寸处理方式`
   改成留白统一或等比裁切（代价是尺寸会被统一）。

### 先预览再决定

```
①加载器 ──文件夹预览图──→ [内置 PreviewImage]
```

先在 PreviewImage 里确认选对了文件夹、图够不够，再往下接处理链。

### 并行多分支

```
①加载器 ──→ ③并行分发器（分支数可调 1~12）
                ├─分支1→ 节点A
                ├─分支2→ 节点B
                ├─分支3→ 节点C
                └─分支4→ 节点D
```

每个分支的图片**各自保持原始尺寸**，可以接到 4 个不同节点，
也可以接到同一个节点的 4 个不同 image 输入口。

## 升级说明

新增控件一律**追加在末尾**（加载器的 `含子文件夹` / `限制最大边长` / `加载模式` /
`单批内存上限`，分发器的 `变尺寸处理方式`），旧工作流打开时前面已有的控件值
不会错位，新控件取默认值。

新增输出同样**追加在末尾**（加载器第 5 个输出 `加载进度`），
已有的 4 个输出位置不变，旧连线不受影响。

行为上有三处变化需要注意：

1. **分发器输出结构修正**（重要 bug 修复）：此前每个元素多套了一层 list，
   导致下游标准节点（KSampler / VAEEncode / SaveImage 等）会报
   `TypeError: unsupported operand type(s) for -: 'float' and 'list'`。
   现在每个元素是张量本身，接任何节点都能跑。
2. 分发器第 3 个输出改名 `执行轮数`，含义改为**下游实际会被调度几次**
   （变尺寸逐张时会大于分组批次数）。`分批清单` 里两个数字都有。
3. **加载器在目录较大时会自动分批**。此前是「一次性全量载入」，现在当预估
   内存超过可用资源的一半时改为惰性分批（详见「惰性分批加载」一节）。
   绝大多数工作流无感；若你的下游依赖「一次拿到全部图片」，
   把「加载模式」设为 `全部载入（不惰性）` 即可回到旧行为。
   注意分批时 `加载数量` 表示**本批**张数，不是目录总数。
